# MetaTech Reborn

**MetaTech Reborn** — мод для Minecraft Forge 1.20.1, объединяющий и переносящий на современную версию механики MetaAdvanced, Greenhouses, экстремального автокрафта и связанных дополнений.

Текущая версия проекта: **0.6.77**. Основная ветка выпуска — **`main`**.

> MetaTech Reborn не заменяет Botania, Re:Avaritia или Applied Energistics 2. Мод добавляет собственные машины и интеграции с ними.

## Требования

| Компонент | Версия | Статус |
|---|---:|---|
| Minecraft | 1.20.1 | обязательно |
| Forge | 47.4.22 или совместимый 47.x | обязательно |
| Java | 17 | обязательно |
| Botania | 1.20.1-454 или новее | обязательно |
| Re:Avaritia | 1.4.1 или новее | для экстремальных рецептов |
| Applied Energistics 2 | 15.x | для ME-автокрафта |
| JEI | 15.x | для просмотра и переноса рецептов |

## Установка

1. Установите Minecraft 1.20.1 и Forge 47.x.
2. Запускайте игру на Java 17.
3. Установите Botania.
4. Для экстремальных рецептов установите Re:Avaritia.
5. Для сетевого автокрафта установите Applied Energistics 2.
6. Для переноса рецептов установите JEI.
7. Поместите один JAR MetaTech Reborn в папку `mods`.
8. Удалите из `mods` все старые версии MetaTech Reborn.

Одновременное наличие двух JAR с `modId=metatech_reborn` приводит к ошибке загрузки Forge.

## Состав мода

В актуальную версию входят:

- многоблочный мана-бур с питанием от Botania Mana;
- теплица Botania с четырьмя слотами модулей и параллельной работой 16 цветков;
- обычный и продвинутый преобразователи удачи;
- объединитель нейтрония;
- энергетическая еда I–IV;
- кодировщик экстремальных шаблонов;
- молекулярный сборщик с сеткой 9×9;
- рецепты Re:Avaritia 3×3, 5×5, 7×7 и 9×9;
- нативная интеграция с AE2;
- перенос рецептов из JEI;
- обычные AE2 Speed Card и Super Speed Card из AE2 Overclocked;
- очищенные GUI и обновлённые игровые текстуры.

## Мана-бур

Мана-бур — многоблочная машина для автоматизированной переработки ресурсов.

Возможности:

- проверка собранности структуры;
- контроллер, корпус, ядро и сопло;
- 81 выходной слот — сетка 9×9;
- модуль добычи;
- улучшения скорости, добычи и генерации;
- питание от маны Botania;
- сохранение состояния в NBT.

В GUI оставлены только:

- текущее и максимальное количество маны;
- прогресс операции;
- состояние структуры.

Лишние подписи, перечисление уровней улучшений и зелёная служебная полоса удалены.

## Теплица Botania

Теплица автоматизирует механики генерирующих цветков Botania.

### Вместимость

- мана: **128 000 000**;
- жидкость: **64 000 мБ**;
- цветочный слот: до **16 одинаковых цветков**;
- слоты модулей: **4**.

До 16 одинаковых цветков могут работать параллельно.

### Модули

- скорость I–III;
- эффективность I–III;
- экономия I–III;
- бесконечный день;
- бесконечная ночь;
- бесконечная вода;
- бесконечная лава.

ID модуля бесконечной воды:

```text
metatech_reborn:greenhouse_infinite_water_module
```

Он предотвращает расход воды рецептами теплицы. Модуль бесконечной лавы выполняет аналогичную функцию для лавы.

GUI теплицы показывает только широкие индикаторы маны и жидкости. Подписи цветка, топлива, модулей, уровней и служебные статусы убраны.

## Преобразователи удачи

В моде есть две самостоятельные машины:

- обычный преобразователь удачи;
- продвинутый преобразователь удачи.

Они имеют разные корпуса и отдельные текстуры передней, боковой, верхней, задней и нижней сторон.

Система поддерживает:

- отдельные входные и выходные банки;
- 81 выходной слот в синхронизированной версии;
- 12 уровней модуля удачи;
- скорость;
- эффективность;
- дополнительные операции;
- удвоение;
- переплавку;
- автоматический вывод;
- питание от Forge Energy.

При обновлении корпусов текстуры существующих модулей и улучшений не заменялись. Концепт-изображения GUI не используются как игровые экраны.

Из GUI удалены подписи входов, выходов, модулей и строка `Удача / операции / FE/т`. Остаются прогресс и короткая причина остановки.

## Объединитель нейтрония

Объединитель нейтрония содержит независимые процессы и собственный выходной банк.

Поддерживаются:

- улучшение скорости;
- улучшение эффективности;
- улучшение выхода;
- сохранение прогресса;
- короткие статусы работы;
- обновлённые фиолетовые текстуры корпуса и улучшений.

Постоянные подписи коллекторов, выходов и улучшений в GUI удалены.

## Кодировщик шаблонов

Кодировщик создаёт экстремальные шаблоны для молекулярного сборщика.

Возможности:

- виртуальная сетка 9×9;
- пустой и закодированный экстремальные шаблоны;
- хранение всех 81 позиций, включая пустые ячейки;
- очистка раскладки;
- призрачный перенос рецепта из JEI;
- центрирование уменьшенных рецептов внутри сетки 9×9.

В GUI оставлены кнопки и короткий статус. Длинная подсказка JEI и постоянные подписи шаблонов удалены.

## Молекулярный сборщик

Молекулярный сборщик работает с сеткой из 81 позиции и поддерживает внутренние шаблоны и задания AE2.

Основные свойства:

- нативная проверка рецепта 9×9 по реальной сетке из 81 слота;
- дополнительные режимы 3×3, 5×5 и 7×7;
- центрирование уменьшенной сетки;
- обязательная пустота за пределами активной уменьшенной сетки;
- защита от списания лишних предметов;
- фиксация активного рецепта;
- сохранение задания, энергии, прогресса и буферов в NBT;
- возврат результата в ME-сеть;
- внутренний банк шаблонов;
- расширение банка шаблонов;
- карты скорости.

GUI очищен от постоянных служебных строк. Оставлены энергия, прогресс и короткий статус.

## Re:Avaritia 3×3–9×9

Поддержка реализована по уровням рецептов Re:Avaritia 1.4.1.

| Верстак | ID | Уровень | Сетка |
|---|---|---:|---:|
| Скалковый | `avaritia:sculk_crafting_table` | 1 | 3×3 |
| Адский | `avaritia:nether_crafting_table` | 2 | 5×5 |
| Верстак Края | `avaritia:end_crafting_table` | 3 | 7×7 |
| Экстремальный | `avaritia:extreme_crafting_table` | 4 | 9×9 |

Для рецепта 9×9 сначала выполняется нативная проверка Re:Avaritia по полному обработчику. Для уровней 1–3 создаётся центрированное представление соответствующего размера.

Предметы вне активной уменьшенной сетки запрещают запуск рецепта. Это предотвращает случайное списание лишнего содержимого остальных ячеек.

## AE2 и JEI

### Applied Energistics 2

При установленном AE2 молекулярный сборщик подключается к ME-сети.

Реализовано:

- собственный декодер экстремальных шаблонов;
- публикация рецептов в ME-сеть;
- атомарная приёмка полного набора ингредиентов;
- запрет частичного списания задания;
- сохранение активной операции;
- возврат результата и контейнеров;
- продолжение операции после перезапуска мира;
- 9 базовых слотов шаблонов;
- расширение банка до 36 слотов;
- четыре слота карт скорости;
- обычная AE2 Speed Card;
- `ae2_overclocked:super_speed_card` при наличии AE2 Overclocked.

AE2 является необязательной зависимостью: без него мод загружается, но ME-автокрафт недоступен.

### JEI

Кодировщик регистрируется для категорий:

- скалкового верстака;
- адского верстака;
- верстака Края;
- экстремального верстака;
- собственных рецептов молекулярного сборщика.

Перенос из JEI заполняет виртуальную раскладку и не перемещает реальные предметы игрока.

## GUI

Цель переработки GUI — убрать текст, перекрывавший слоты или выходивший за границы панелей.

Принципы версии 0.6.77:

- постоянные служебные подписи скрыты;
- короткие ошибки остаются видимыми;

- слоты и контейнерная логика не менялись при очистке текста;
- изображения-концепты GUI не подменяют реальные кодовые экраны.

## Сборка

Требуется Java 17.

### Linux/macOS

```bash
gradle build --no-daemon
```

### Windows

```bat
gradle.bat build --no-daemon
```

Готовый JAR появляется в:

```text
build/libs/
```

Этапы сборки:

1. извлечение базового пакета ресурсов;
2. применение исправлений исходников;
3. установка синхронизированных ресурсов;
4. очистка GUI-текстов;
5. компиляция Java 17;
6. обработка ресурсов;
7. reobfuscation Forge JAR;
8. автоматическая проверка GitHub Actions.

## GitHub Actions

Workflow `.github/workflows/main.yml` запускается при push в `main`, push в `agent/**`, pull request в `main` и вручную.

CI выполняет:

- сборку Gradle на Java 17;
- проверку инвентаря молекулярного сборщика по байткоду;
- проверку AE2 event listener;
- проверку обязательных классов и ресурсов;
- разбор всех JSON;
- проверку структуры и CRC всех PNG;
- проверку локализации;
- загрузку единого JAR как Actions artifact.

Успешная компиляция и проверка ресурсов не заменяют полный игровой тест.

## Диагностика

### Exit code 1 без crash-report

Проверьте:

1. `logs/latest.log`;
2. отсутствие нескольких JAR MetaTech Reborn;
3. использование Java 17;
4. версии Forge и Botania;
5. целостность `META-INF/mods.toml`.

Ошибка TOML возникает до полноценной загрузки модов, поэтому обычный crash-report может не создаваться.

### Игра запускается без мода, но падает с ним

Для диагностики нужны:

```text
logs/latest.log
crash-reports/<самый новый файл>.txt
```

Второй файл может отсутствовать, если ошибка произошла на этапе чтения метаданных.

### Рецепт 5×5 или 7×7 не запускается

Проверьте:

- установлен ли Re:Avaritia нужной версии;
- выбран ли рецепт из правильной категории JEI;
- пусты ли ячейки вне активной сетки;
- подключён ли Pattern Provider AE2;
- хватает ли энергии и места для результата.

### Текстуры выглядят старыми

Удалите старый JAR и все дубликаты из папки `mods`. Forge загружает ресурсы из установленного JAR, а не из референсов.

## Структура репозитория

```text
.github/workflows/       GitHub Actions
src/main/java/           исходный код Java
src/main/resources/      ресурсы Forge
src/generated/           сгенерированные исходники
tools/                   скрипты синхронизации и ресурсные пакеты
docs/                    changelog, roadmap и технические заметки
dist/                    информация о тестовой сборке и контрольные суммы
```

Ключевые файлы:

- `build.gradle` — зависимости и задачи Gradle;
- `gradle.properties` — версии Minecraft, Forge и мода;
- `src/main/resources/META-INF/mods.toml` — метаданные Forge;
- `tools/install_gui_text_cleanup.py` — очистка локализации GUI;
- `.github/workflows/main.yml` — автоматическая сборка и проверки.
